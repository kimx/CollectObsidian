# 📎 非設計背景，如何用 Codex 做出高級感網站？

## 摘要

> 這篇實戰分享主張「先設計、後開發」：先讓 Codex 依需求與參考整理出 DESIGN.md，確認風格與邊界後再寫程式，能明顯降低 AI 模板感，讓網站更有個人表達。

## 重點

- 先要求 Codex 輸出 DESIGN.md（頁面目標、受眾、色彩、字體、版面、動效與禁忌）再開始實作
- 參考來源可分為三類：可直接借風格的平台、可抽取設計規則的既有網站、靈感蒐集站
- 借鑑原則是「學風格，不抄品牌」，避免直接複製 Logo、文案、圖片與完整結構
- 若沒有設計背景，可用結構化提示詞要求 Codex 先提煉設計語言，再進入程式階段
- 首版結果不佳時，應讓 Codex 先比對 DESIGN.md 找出問題（首屏表達、色彩、字級層次、卡片模板感、行動版溢出）
- 視覺素材品質會直接影響成品質感，必要時先生成/替換素材再調整 CSS

## 可行動事項

- [ ] 以個人站為題材，先提供 3 個參考來源，要求 Codex 產出 DESIGN.md 並逐項確認後才開始寫頁面。
- [ ] 首版完成後，要求 Codex 先列出 5 個和 DESIGN.md 不一致的點，再逐項修正。

## 原文整理

- 常見失敗起手式是直接要求「做一個高級感網站」，容易得到套版化結果
- 建議流程：先彙整參考 → 產生 DESIGN.md → 人工確認 → 依設計稿實作 → 瀏覽器檢查與迭代
- 參考工具包含 Refero Styles、web-to-design-md、Mobbin、Page Flows、Recent、Collect UI、Lapa Ninja、React Bits 等
- taste-skill 可協助風格還原、去 AI 味與視覺生成；若素材不理想可搭配 Imagen 生成替換
- 用 Cowart 無限畫布進行參考圖、現況截圖與素材對照，可提升「感覺不對」問題的溝通效率
- 作者最終結論：Codex 在 UI 場景要被視為可協作打磨的設計夥伴，而非一次生成器
