[最近準備在原本的 AI Agent 課程裡， 完整的加上 Microsoft Agent Framework（MAF）的介紹。 愈玩愈有一種感覺： 現在要做一個 AI Agent， 真的已經快變成彈指之間的事情了。 如此一來，真正重要的，反而不是 AI Agent 本體。 而是： 「這個 Agent 到底能做什麼？」 當 Skill 機制開始成熟，AI Agent 本體和能力，其實正在慢慢解耦。 Agent 本身負責理解與決策， 真正做事的能力，則透過不同 Skill 動態掛載。 而 MAF 在這塊做得很漂亮。 幾行程式碼，Agent 就能自動發現 Skill、自動建立 Function Calling，自己決定什麼時候該用哪個 Skill。 我覺得這不只是開發框架的革新， 也是下一代應用架構正在開始改變的訊號。 傳統應用程式正在逐漸消失。 AI Agent 正在崛起。 ---- 我把文章和 repo 放在底下第一個留言。](https://www.facebook.com/DotNetWalker/posts/pfbid02ehHKiGqP6edrWxVdvfHnavwn8YWz3uA8xbmX7ehu3VfCmEjU5H4bwBV2cfktC5eol)[最近在讀《比賽，從心開始》時，書中提到的「自我一」與「自我二」兩個自我的概念架構，感覺很適合拿來延伸，作為理解 AI 與工程師的協作。 自我一負責行動與直覺產出，自我二負責觀察、批判與修正。 放進 AI 開發流程後會變成： 人定義規格 → AI 產生程式 → 人 code review → AI 修正 → 持續迭代 AI 很像高速運作的自我一，能快速產生結果； 工程師則像自我二，負責判斷： - 架構是否合理 - 邊界是否完整 - 邏輯是否正確 - 系統是否可維護 工程師的角色從產出程式交付價值，變成批判程式凝聚價值。 過去重點是「自己寫 code」，現在更重要的是「是否能持續驗證與修正 AI 的輸出」。 這情景中 AI 並沒有取代工程師，而是讓「產生 → 批判 → 修正」這個循環被極速放大。 但如果沒有強大的自我二，高速的自我一，只會更快產生大量錯誤，價值可能越走越偏。因此，未來工程師真正的核心能力，可能不再只是 coding 而是批判、判斷與迭代能力。](https://www.facebook.com/poychang.tech/posts/pfbid022hqfMFC4QJ9cb5LbzSQcS5Lix5fpAEik3s7aYa37eSmf6ND3NMecNbN5fFZszeRwl)[網路上都在講 Visual Studio Code 上如何使用 Agent Skills，系出同名的 Visual Studio 也可以玩呀，雖然有些細節不太一樣，像是內建給 Agent 的工具名稱就差滿多的。 也因此寫了幾篇在 Visual Studio 中使用 GitHub Copilot 的文章，最新一篇是在 Visual Studio 中使用 Agent Skills，其中我採用.NET File-based App 來開發 Agent Skills 😃](https://www.facebook.com/poychang.tech/posts/pfbid0AKvXr6u1iUusj4TjiyemGtJtvyT4yKC3RzYJMEwBJTGMs6Du3ubeBDwHWVfzsFU4l)
