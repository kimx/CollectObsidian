[📌 善用 HTML 輸出: Markdown 給 AI 讀，HTML 給人類看 Anthropic 工程師 Thariq 最近發了一條推文「HTML is the new markdown」，說他幾乎不再寫 markdown 了，全部改用 Claude Code 直接生成 HTML。這條推文超過四百萬次觀看，還引來 Karpathy 的長篇回應。 這背後的洞見不只是「換個格式」這麼簡單。 🔍 為什麼 HTML 比 Markdown 好看這麼多? Markdown 的視覺表達能力很有限: 沒有版面配置、沒有色彩、沒有互動元素。HTML 則可以有卡片式佈局、資料圖表、摺疊面板、分頁切換、甚至互動功能 — 而且 AI 都能直接生成，不需要你寫 CSS 或 JavaScript。 Thariq 做了一個範例展示頁，列出 20 種 HTML 輸出的實際用途: ▸ 方案並排比較、實作計畫 ▸ 帶註解的 PR diff、模組地圖 ▸ 設計系統色票、動畫沙盒 ▸ 方向鍵簡報、週報儀表板 ▸ 拖放式看板、Prompt 調校工具 全部都是單一 HTML 檔，瀏覽器打開就能用。 —— 🧠 Karpathy 的觀點: AI 輸出格式的進化 他提出了進化路線: 純文字 → Markdown → HTML → 互動式神經影像。核心論點是人腦有三分之一專做視覺處理，視覺是資訊進入大腦的「十線道高速公路」，AI 的輸出當然應該往更視覺化的方向走。 —— ⚖️ 關鍵區分: 這不是取代 Markdown Markdown 的價值有兩層: ▸ 給人類的清晰摘要 ▸ 給模型的 token 效率格式 HTML 只解決第一個。正確的理解是: ▸ Markdown 是 AI 讀寫的好格式 — token 效率高 ▸ HTML 是給人類看的好格式 — 視覺豐富、可互動 兩者不是取代關係，關鍵是搞清楚輸出是給誰看的。 —— 📊 實測 20 個 Prompt: 最值得學的場景 有人把 20 個範例全部重新測試，HTML 贏了 17 場。最大的幾個亮點: ▸ Code Review: 同一個 612 行 PR，markdown 版 90 秒掃完就跳過](https://www.facebook.com/xia.aihao/posts/pfbid025vbApH4sbP2iEz3vqbGkTnhH5B3tnQSvjLM6493jdTUUKDu9KrQd7pcDkDvtFtEVl)[最近在讀《比賽，從心開始》時，書中提到的「自我一」與「自我二」兩個自我的概念架構，感覺很適合拿來延伸，作為理解 AI 與工程師的協作。 自我一負責行動與直覺產出，自我二負責觀察、批判與修正。 放進 AI 開發流程後會變成： 人定義規格 → AI 產生程式 → 人 code review → AI 修正 → 持續迭代 AI 很像高速運作的自我一，能快速產生結果； 工程師則像自我二，負責判斷： - 架構是否合理 - 邊界是否完整 - 邏輯是否正確 - 系統是否可維護 工程師的角色從產出程式交付價值，變成批判程式凝聚價值。 過去重點是「自己寫 code」，現在更重要的是「是否能持續驗證與修正 AI 的輸出」。 這情景中 AI 並沒有取代工程師，而是讓「產生 → 批判 → 修正」這個循環被極速放大。 但如果沒有強大的自我二，高速的自我一，只會更快產生大量錯誤，價值可能越走越偏。因此，未來工程師真正的核心能力，可能不再只是 coding 而是批判、判斷與迭代能力。](https://www.facebook.com/poychang.tech/posts/pfbid0365KqyGYgS7bv8x9gkZPyCaFX8uhCzkjBMhaucGmAAqm2BLiZoo3o9UdUZhWDZFmDl)[網路上都在講 Visual Studio Code 上如何使用 Agent Skills，系出同名的 Visual Studio 也可以玩呀，雖然有些細節不太一樣，像是內建給 Agent 的工具名稱就差滿多的。 也因此寫了幾篇在 Visual Studio 中使用 GitHub Copilot 的文章，最新一篇是在 Visual Studio 中使用 Agent Skills，其中我採用.NET File-based App 來開發 Agent Skills 😃](https://www.facebook.com/poychang.tech/posts/pfbid02EBNF2mpqZxQfKFoFYxgpWUX1bKaqEqSNwQDtMb5tCGnUDwZe3GddzXH9hjfkfyfUl)[看完這支韓國金教授的影片，我有點想衝去把鍵盤親一下。 （os：講真的，這就是我這半年每天在做的事，但他用一個我從來沒聽過的詞講清楚了——vibe coding。） 金益翰教授（김익한）是韓國「記錄學者」這領域的代表人物，台灣比較少人認識他。這支影片的緣起很有意思：他被 NC Soft（韓國最強的軟體公司之一）邀請去總部對 300 個工程師演講，題目叫「記錄學者怎麼用 AI」。 一個不是工程師的人，跑去跟一群工程師講 AI。他自己說那一刻「胸口一陣堵」。 於是他做了一件事—— 演講前三週，他清晨起床，打開 Claude Code，用一天的時間做了一個 app。一個叫「極致記錄（지독한 기록）」的個人記錄系統。然後他帶著這支 app 走進 NC Soft，當場 demo 給工程師看。 ▋ 什麼是 vibe coding？ 金教授定義得很有畫面感：vibe 在英文裡有「振動」「感覺」「來回對話」的意思。vibe coding 就是用嘴巴寫程式，用感覺寫程式，跟 AI 一來一往，code 就慢慢長出來了。 但不是隨便講。他列了五個你腦袋裡一定要有的東西： 1. 目的：這東西做來幹嘛？給誰用？ 2. 輸入：使用者要怎麼餵資料進去？ 3. 處理流程：每一步怎麼動？ 4. 判斷標準：要做決定的時候，依據什麼？ 5. 輸出：最後跑出來長什麼樣？ ▋ 我看完最震撼的一句話 他說：「記錄學者其實是最適合做 vibe coding 的人，因為我們本來就在練習，把腦袋裡那團模糊的東西寫成具體的步驟。」 我整個愣住。 以前我以為「會寫程式」是某種技術門檻，現在我發現真正的門檻是——你能不能把一件事的流程，講清楚、寫下來、想完整。 工程師之所以會做產品，不是因為他們會打 code，是因為他們腦袋習慣這樣思考。 而做田野記錄、做課堂筆記、做共備紀錄、做學習歷程的人——其實一直在練同一件事，只是我們從來沒意識到。 ▋ 我自己的現場 我這學期帶八年級「自我領導力」彈性課，柯維《七個習慣》是核心教材。 第二個習慣叫「以終為始」——做任何事之前，先在腦袋裡走一遍。 第三個習慣叫「要事第一」——先處理重要但不緊急的，不要被緊急但不重要的綁架。 我突然發現，金教授講的「vibe coding 五要素」，根本就是七個習慣的具體版： - 目的＝以終為始 - 處理流程＋判斷標準＝要事第一 - 輸出＝你想活成什麼樣子 我打算下週上「以終為始」的時候，直接帶 14 歲的孩子做一次微型 vibe coding 練習——不寫程式，只練「把一件你想做的事，五個要素全部寫出來」。 主動積極不是口號。是你願不願意打開 Claude Code，輸入第一行字。 ▋ 我的結論 金教授最後講了一句我抄在筆記本上：「AI 不是取代你，是要你帶著它一起生活。」 不是「我、AI」兩位一體，是「我、記錄、AI」三位一體。 你不寫，AI 就沒有東西可以接住你。 你寫得越具體，AI 給你的回禮就越驚人。 謝謝金教授把我這半年含含糊糊在做的事，講成了這麼清楚的一套方法。 也謝謝願意看到這裡的你——如果你以前覺得「coding 跟我沒關係」，這支影片真的值得花 32 分鐘。 下一個一天做出 app 的人，可能就是你。 🎬 原片：https://www.youtube.com/watch?v=54jRLzT7KEI](https://www.facebook.com/hk6429/posts/pfbid0zzgJ4vozxpwyCdXxXkjHnKmQzEAsHZ77R5fdpcqMTiPBZnGt2fWinGF9tuQkPcdyl)
